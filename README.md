# Проверка фотографий повреждённых посылок

Портфолио-проект по Computer Vision для модерации обращений о повреждённых посылках. Модель по одному реальному фото выделяет коробку и оценивает выраженность видимых признаков повреждения. Отдельное демо показывает, как обработать несколько ракурсов и запросить пересъёмку при нехватке данных.

| Эксперимент на 24 отложенных фото | Average Precision |
|---|---:|
| HOG + SVM по всему кадру | 0,493 |
| MobileNetV3 + логистическая регрессия по всему кадру | 0,531 |
| MobileNetV3 + логистическая регрессия с автоматической рамкой | 0,797 |
| MobileNetV3 + логистическая регрессия с ручной рамкой | 0,838 |

Основная выборка содержит 156 снимков реальных коробок. Результат с автоматической рамкой зависит от условий съёмки. Протокол, контроль по фону и отдельная проверка на снимках из пункта выдачи описаны в [итоговом отчёте](FINAL_RESULTS.md). Код скачивает исходные снимки из зафиксированной версии датасета и проверяет контрольные суммы.

## Быстрый запуск

Нужен Python 3.10 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-demo.txt
python parcel_cv.py demo
python -m streamlit run demo_app.py
```

На Windows окружение можно активировать командой `.venv\Scripts\activate`. Команда `demo` генерирует снимки, обучает модели и сохраняет результаты в `run/demo/`. Интерфейс открывает примеры из отложенного теста. В примере с повреждением на втором снимке убери галочку второго фото, чтобы сравнить маршруты. В разделе «Мои фото» можно выбрать до двух изображений и задать ракурс.

Проверка одного снимка через терминал:

```bash
python parcel_cv.py predict run/demo/model.joblib front=data/demo/images/box-0073-0.jpg
```

Установка из `requirements.txt` достаточна для командной строки. Файлы моделей `joblib` загружай только из доверенного источника.

## Многокадровый прототип на синтетических данных

150 синтетических посылок, по два снимка на обращение. На изображениях варьируются цвет, фон, освещение, размытие и кроп. Есть разрывы, проколы, смятые углы и повторяющиеся ракурсы. Разбиение по физическим коробкам: 90 для обучения, 30 для подбора модели и порогов, 30 для теста.

Модель качества фото — логистическая регрессия. Модель повреждений сравнивает логистическую регрессию и Extra Trees на одинаковых признаках цвета и границ. Признаки агрегируются по участкам кадра. Если высокий балл повреждения получен на пригодном снимке, обращение помечается как видимое повреждение. Для маршрута «повреждений не видно» нужны оба заявленных ракурса и низкий балл. Если ракурсов не хватает, запрашиваются фото, а при промежуточном балле с достаточными ракурсами нужна ручная проверка.

Для выбора модели и порогов используется условная стоимость ошибки на валидации: 5 за пропуск, 3 за ложный сигнал и 1 за ручную проверку или запрос снимков. Эти веса заданы для демонстрации. При равной стоимости выбирается вариант с меньшим числом ошибок, затем с большим охватом. Выбрана логистическая регрессия с порогами 0,20 и 0,80. Average precision для видимых повреждений на пригодных тестовых кадрах — 0,929 у логистической регрессии и 0,848 у Extra Trees.

| Результат на тесте | Только первое фото | Все фото |
|---|---:|---:|
| Обращений с автоматическим маршрутом | 2 из 30 | 14 из 30 |
| Повреждений, отмеченных автоматически | 2 из 13 | 5 из 13 |
| Повреждённая посылка с маршрутом «повреждений не видно» | 0 | 1 |
| Ложный сигнал о повреждении у целой коробки | 0 | 0 |

Политика требует оба ракурса для ответа «повреждений не видно», поэтому общий охват в колонках зависит и от этого правила. На втором фото обнаружены три дополнительных повреждения. В одном случае система пропустила вмятину угла (`box-0045`), ещё две вмятины ушли на проверку и одна — на пересъёмку. Это повод отдельно проверить малые деформации углов на новых коробках. Все числа относятся к этому синтетическому тесту. Для оценки качества на реальных данных нужна отдельная выборка фотографий.

`example-results/` содержит метрики, разбиение и выгрузку ошибок. После запуска `demo` в `run/demo/analysis.sqlite` доступна таблица тестовых обращений. Запрос в `analysis.sql` группирует результаты по типу дефекта и маршруту.

## Сбор реальных многокадровых обращений

Снимай упаковки без видимых имён, адресов и читаемых номеров отправлений. Для первого сбора можно использовать 30 обращений, чтобы проверить инструкцию, затем добавить новые коробки и трудные случаи: блики скотча, тёмные сгибы, наклейки, мелкие вмятины. Попроси второго разметчика независимо оценить часть снимков и зафиксируй причины расхождений. Для проверки модели зарезервируй отдельные коробки, которые не использовались при разработке правил.

```csv
path,box_id,claim_id,face,usable,visible_damage,claim_damaged,defect,condition
images/parcel01-front.jpg,parcel01,claim01,front,1,0,1,dent,clear
images/parcel01-back.jpg,parcel01,claim01,back,1,1,1,dent,clear
images/parcel02-front.jpg,parcel02,claim02,front,0,,0,none,blur
images/parcel02-back.jpg,parcel02,claim02,back,1,0,0,none,clear
```

- `path` — путь относительно файла разметки. `box_id` — один ID на физическую коробку, даже если снимки сделаны в разные дни. `claim_id` объединяет кадры обращения.
- `face` — сторона, которую снимали, `front` или `back`. Текущая версия использует переднюю и заднюю стороны.
- `usable` — видно ли нужную сторону достаточно хорошо для проверки. Сильное размытие, темнота или обрезка могут сделать кадр непригодным.
- `visible_damage` — видно ли повреждение на пригодном кадре. Для непригодного кадра оставь поле пустым. На пригодном фото целой стороны повреждённой коробки поставь 0.
- `claim_damaged` — состояние коробки по осмотру или по отдельному набору контрольных фото. `defect` — основной тип повреждения всей коробки. `condition` — условие съёмки.
- Для обучения нужны пригодные и непригодные снимки, а среди пригодных нужны кадры и с повреждениями, и без них.

```bash
python parcel_cv.py train path/to/manifest.csv --out run/custom
```

Чтобы оценить следующую модель на тех же коробках, оставь состав и ID выборки неизменными. Новый набор данных получает собственное разбиение. Первое расширение после получения реальных фото — сравнить эти две модели с эмбеддингами предобученной CNN и отдельно оценить вмятины, проколы и разрывы.
